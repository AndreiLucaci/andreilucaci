### About me

I'm Andrei, a software engineer from Cluj-Napoca, Romania, building software professionally since 2014.

I've worked as a **founding engineer, software architect, technical lead, and individual contributor**, across startups, financial technology, enterprise platforms, and industrial software.

My strongest area is back-end engineering, particularly **.NET and distributed systems**, but I've spent years working across the stack, from React interfaces and Node.js services to cloud infrastructure and production operations.

I enjoy understanding how things work, questioning unnecessary complexity, and building systems that are easier to reason about, maintain, and evolve.

I believe good engineering requires more than writing good code. It requires sound judgment, understanding the problem, and knowing when *not* to build something.

Outside engineering, I'm a husband, a father, a Christian, and someone who enjoys studying Scripture, playing the piano, and building things simply because they interest me.

### What I work on

My professional focus is designing and developing distributed, cloud-native systems.

Currently, I work at **[ifm](https://www.ifm.com)**, contributing to the **moneo industrial IoT platform**, particularly its data processing and compute infrastructure.

Some of the areas I work with regularly:

- **Distributed architecture:** Microservices, messaging, asynchronous processing, service boundaries, and reliability.
- **Data engineering:** Time-series processing, multi-tenant data pipelines, ClickHouse, PostgreSQL, and high-volume data exports.
- **Cloud infrastructure:** Kubernetes, Docker, Helm, AWS, Azure, and CI/CD.
- **Software design:** Clean Architecture, Domain-Driven Design, dependency management, and separation of concerns.
- **Observability:** OpenTelemetry, structured logging, tracing, and production diagnostics.
- **Engineering leadership:** Technical direction, architectural decisions, code reviews, mentoring, and balancing quality with delivery.

I care particularly about keeping architectural boundaries meaningful, avoiding unnecessary abstractions, and ensuring that complexity is justified by the problem being solved.

### Things I've built

**[PureKey](https://purekey.dev)**

*What you type is what you typed.*

A minimal iOS keyboard built around a simple idea: a keyboard should type exactly what you press.

No autocorrection, no predictions, no adaptive key behavior. Just a predictable typing experience.

Built with Swift, with an emphasis on precision, simplicity, and privacy.
